# Tests

Test locations are reserved, not implemented. No test runner, test files or passing results exist yet.

- unit: deterministic patch planning, binding and review rules; no network.
- integration: server authorization, persistence and controlled provider adapter behavior.
- e2e: complete browser flows, keyboard/error handling and clearly labeled sample/live paths.
- fixtures: synthetic, non-sensitive example inputs only.

Use the [acceptance matrix](../docs/engineering/validation.md) to decide tests when implementation starts. A mocked API success must not be mistaken for a real Buffer integration. Live test drafts and credentials require their own authorization.
